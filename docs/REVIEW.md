## Оставшиеся границы безопасности

- Это frontend-first демо. Пароль `demo`, роли и все данные доступны владельцу браузера через DevTools/localStorage. Скрытие себестоимости в mock-ответе не защищает её от человека с доступом к этому браузеру. Здесь нельзя хранить настоящие персональные или платёжные данные и вести реальную кассу.
- Mock receipts теперь сохраняются вместе с локальным Workspace, а pending-команда — отдельно до результата. Это не защищённое серверное хранилище: PostgreSQL должен сохранять ключ, hash и результат транзакционно с деньгами/складом.
- Обнаружение устаревшей вкладки защищает обычные последовательные записи, но localStorage не имеет атомарного compare-and-swap между процессами. Демо допускает одну рабочую вкладку; конкурентные кассы требуют backend-блокировок.
- P2P — явно помеченные fixtures. Ни достоверный источник Telegram Business, ни реальная авторизация, неизменяемый серверный аудит, возвраты и DB-транзакции ещё не реализованы.
- Нулевой npm audit не означает отсутствия неизвестных уязвимостей. Проверка не включает production-инфраструктуру, которой пока нет.

Для честного повторения в демо mock-idempotency receipts сохраняются атомарно **в той же localStorage-записи**, что и Workspace. Старая запись Workspace читается без удаления истории; отсутствующая разбивка старого производного report мигрируется, затем пересчитывается. Это локальная имитация серверного журнала, не гарантия PostgreSQL. Ошибка сохранения не коммитит новое состояние; ошибка удаления pending не даёт автоматически новый ключ. Демо по-прежнему рассчитано на одну рабочую вкладку; backend должен обеспечить транзакции и защиту конкурентных касс.

Защита `requestEpoch` сохранена. Pending не означает серверное подтверждение оплаты/закрытия; offline-команды не отправляются и не подтверждаются. API/auth-ответы не попадают в app-shell cache. Новые регрессии не заменяют и не ослабляют прежние сценарии.

Формат локального демо-хранилища теперь version=1 с workspace и receipts. Для отката к старой версии сначала экспортируйте демо-запись; старый код не умеет читать envelope. Не очищайте хранилище для обхода ошибки и не стирайте pending при неразрешённом результате. Серверная сверка/разрешение конфликтов остаётся задачей backend-этапа.

Результаты локального прогона: `npm run check:contract` — без drift; `npm test` — 38 tests / 7 files; `npm run build` — успешно; `npx playwright test --workers=2` — 20/20 (desktop/mobile, включая старый polling regression и оба каталога). Скриншоты из повторного технического прогона не включаются в исправления: они генерируются тестами и доступны как CI artifacts; оформление не перерабатывается. ## Follow-up review PR #3

Оба новых regression tests сначала воспроизвели дефекты: refund без CSRF в OpenAPI и полный список чужих переводов. Refund и logout теперь явно требуют X-CSRFToken; тест выполняет настоящий session login и refund с отсутствующим/ошибочным/правильным токеном. Transfer selector общий для read API: owner/manager видят все; cashier — только связанные оплаты своих смен **и** своих счетов, плюс непривязанные уведомления от открытия текущей собственной смены до server now с положительной суммой не больше долга одного из awaiting_payment счетов этой смены. Без открытой смены кандидаты не выдаются. Это правило видимости, не подтверждение перевода. Есть проверки чужой смены, старого/будущего/слишком большого перевода и полного списка управляющего.

Остальные большие пробелы аудита вынесены в последовательные зависимые изменения: сотрудники/пароли/rate limit/QR и bounded workspace/history. PR #2 остаётся открытым; его код/ветка не меняются.
