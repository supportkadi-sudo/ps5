# Новый интерфейс и полный каталог экранов

Светлая нейтральная оболочка с синим акцентом. Цвета статусов отделены от основных действий: зелёный — игра, янтарный — ожидание оплаты, серый — свободная кабинка. Это интерфейс работающей React CRM на mock API, не отдельные нарисованные макеты.

## Компоновка

- Светло-серая боковая панель и компактные карточки кабинок вместо тёмно-зелёного меню и крупных пустых карточек.
- Начиная с 1380 CSS px выбранный счёт и кабинки видны одновременно. На меньшей ширине счёт открывается отдельным экраном. На 1280 сохраняется обычная двухколоночная детализация с итогом справа.
- На телефоне кабинки представлены компактными строками, а снизу закреплены зал/счета, смена, товары (при наличии прав) и остальные разделы.
- Запуск, предчек, переход к оплате, приём части и подтверждение закрытия закреплены над мобильной навигацией в соответствующем состоянии. Получение оплаты и закрытие остаются разными действиями.
- Способ оплаты выбирается крупными кнопками; P2P-уведомления раскрываются отдельно. Демо-статус не скрыт.
- Редактирование товара, тарифа, кабинки, способа оплаты, ссылки и роли открывается в native dialog: фокус ограничен формой, есть отмена и Escape. Обычные кассовые/приходные формы остаются внутри своих разделов.
- Каталог на телефоне показывает все финансовые поля в карточках без горизонтального скролла. Наценка и маржа сохранены.

## Все скриншоты

[Нумерованный список каждого снимка](screenshots/redesign/README.md) · [Галерея с поиском](screenshots/redesign/gallery.html).

Покрытие: вход/ошибка, пустой зал, меню, смена/расход/пересчёт/расхождение, создание счёта, все состояния таймера, товары и удаление с причиной, предчек и печать, наличные/P2P/частичные/полные оплаты, отдельное закрытие, история и до/после, фильтры зала, каталог, создание/изменение товара, поступления и корректировки партий, тарифы, кабинки, методы оплаты, отзывы/QR/печать, сотрудники/права, отчёт/ошибка периода, аудит, отсутствие сети и различия ролей.

Телефон: реальные последовательные viewport-снимки 393 × 852 CSS px с перекрытием при прокрутке. Благодаря этому фиксированная кнопка на одном кадре не скрывает содержимое на следующем. Десктоп: полная страница при viewport 1440 × 1000. Формы и состояния подписаны; длинные страницы имеют несколько частей. Это перечень реализованных экранов, а не обещание экранов отсутствующего backend.

Воспроизведение: `cd frontend && npm run screenshots`. Затем `python scripts/build-screen-gallery.py` (Python + Pillow) создаёт контактные листы, галерею и переносимые HTML/ZIP. Переносимые экспорты не дублируются в git; исходные PNG и каталог сохранены. CI сохраняет исходные снимки в artifact `web-test-results`.

## Проверки и ограничения

29 unit/API/storage tests; 14 Playwright cases для desktop/mobile, включая полные каталоги. Responsive-проверка 360/393/768/1280/1440: отсутствие переполнения, итог до формы на узком экране, вкладки от 44 px, мобильный каталог, закрытие меню и отсутствие pageerror. Production build и генерация типов без drift прошли. Изменения относятся к представлению/навигации, без изменения API и расчётов.

Проверено в Chromium с мобильной эмуляцией; физический Android, экранная клавиатура, Safari/iOS и печать на реальном принтере не проверены. Адаптация нужна для реализованного web/mock этапа; это не готовая production-касса. Откат — revert коммита редизайна, миграций и изменений реальных данных нет.
